01 · VISÃO GERAL

O que é o n8n

O n8n é uma plataforma de automação visual. Um workflow recebe um evento, processa dados em uma sequência de nodes e pode chamar APIs, bancos de dados ou modelos de IA. É uma ferramenta low-code: muitas automações não exigem código, mas conhecer JSON, HTTP e expressões ajuda a criar fluxos mais confiáveis.

Onde ele se encaixa

Use o n8n para conectar sistemas e automatizar processos. O Open WebUI é a interface de conversa, o Flowise é um construtor de cadeias e agentes, e o n8n coordena etapas e integrações. Ele não traz um modelo de linguagem próprio: neste laboratório, os modelos são servidos pelo Ollama e acessados pelo LiteLLM.

Um fluxo pode iniciar manualmente, em um horário definido, por uma chamada HTTP recebida (webhook) ou por um evento de uma integração. O node HTTP Request permite conectar APIs mesmo quando não existe um node específico para o serviço.

02 · PRIMEIRO ACESSO

Iniciar e abrir o serviço

  1. Abra o dashboard do Laboratório e inicie o serviço n8n Orchestrator. Se o laboratório inteiro não estiver ativo, o PostgreSQL também precisa estar em execução.
  2. Acesse http://localhost:5678. Na primeira utilização, crie a conta proprietária solicitada pelo n8n. Cada instalação local mantém seus próprios usuários e workflows.
  3. Na lista de workflows, crie um fluxo novo e dê a ele um nome que explique o objetivo, por exemplo Consultar saúde do MCP.

O n8n pertence aos perfis Compose full e workflows. Se estiver usando o terminal na pasta do projeto, também é possível iniciar o perfil de workflows com o comando abaixo; o Compose inicia as dependências necessárias.

docker compose --profile workflows up -d n8n
Se a tela não abrir

Confirme no dashboard que n8n e PostgreSQL estão ativos. O painel usa a porta local 5678; se outro programa já estiver usando essa porta, o container pode não iniciar. Veja também Diagnóstico.

Persistência

Workflows, credenciais e estado ficam no banco n8n_db e no volume n8n_storage.

Chave de criptografia

A configuração do projeto usa N8N_ENCRYPTION_KEY no arquivo local .env. Preserve essa chave ao fazer backup ou reinstalar.

03 · FUNDAMENTOS

Como um workflow funciona

Trigger (gatilho)
Inicia uma execução: por exemplo, Manual Trigger, Schedule Trigger ou Webhook.
Node
Uma etapa que recebe dados, executa uma ação e envia o resultado adiante.
Conexão
Linha que define para onde a saída de um node é enviada. Ramos diferentes podem tratar condições distintas.
Item e JSON
Os nodes normalmente trocam uma lista de itens. Cada item contém dados JSON e pode conter dados binários, como arquivos.
Credencial
Conjunto protegido de dados de autenticação reutilizável por um ou mais nodes.
Execução
Uma rodada do workflow. O resultado de cada node ajuda a localizar erros e entender a transformação dos dados.

Mapear e transformar dados

Abra o painel Input de um node para inspecionar os dados recebidos. Para reutilizar um valor, selecione-o no painel ou use uma expressão. Por exemplo, {{ $json.nome }} lê nome do item atual; em um webhook, o corpo costuma estar em {{ $json.body.pergunta }}. Os nomes de propriedades dependem do JSON real de entrada.

O node Edit Fields (Set) é útil para criar, renomear ou remover campos. Nodes como If, Switch, Merge e Loop Over Items controlam o caminho. Para aprender a expressão certa, execute o fluxo com dados de teste e inspecione o Input antes de mapear os campos.

04 · EXERCÍCIO 1

Consultar a saúde da API Python MCP

Este exercício faz uma chamada HTTP de dentro do n8n para outro serviço do laboratório. Os containers compartilham a rede Docker; por isso, o endereço usa o nome do serviço python-mcp, e não localhost.

Manual Trigger→HTTP Request→Inspecionar JSON
  1. Adicione o node Manual Trigger. Ele permite iniciar o exercício pelo botão de execução, sem publicar o workflow.
  2. Adicione HTTP Request e conecte a saída do gatilho a ele.
  3. Configure Method como GET e URL como http://python-mcp:8000/health. Não é necessária autenticação para esse endpoint dentro da rede local do compose.
  4. Execute o workflow. Se a resposta indicar status: healthy e service: python-mcp, a chamada funcionou. Se houver erro de conexão, confirme que Python MCP está iniciado no dashboard.
Exemplo de resposta
{
  "status": "healthy",
  "service": "python-mcp",
  "version": "3.0.0",
  "mcp_server": "GenAI-MCP-Server"
}

Como próximo passo, altere a requisição para POST http://python-mcp:8000/run-task e envie o corpo JSON { "task_type": "status" }. Essa tarefa consulta os serviços do laboratório e devolve um relatório; serviços opcionais desligados aparecerão como offline.

05 · EXERCÍCIO 2

Criar uma API de perguntas com o LiteLLM

Neste workflow, um webhook recebe a pergunta, o HTTP Request envia o texto ao endpoint compatível com OpenAI do LiteLLM, e Respond to Webhook devolve a resposta ao cliente.

Webhook→HTTP Request · LiteLLM→Respond to Webhook

Etapa A · Configurar o webhook

  1. Crie um workflow novo e adicione Webhook como primeiro node.
  2. Configure HTTP Method = POST, Path = perguntar e Respond = Using Respond to Webhook Node.
  3. Para testar, selecione a URL de teste e clique em Listen for Test Event (ou no botão equivalente da sua versão). Mantenha essa espera ativa enquanto envia a chamada de teste abaixo.

Etapa B · Chamar o modelo

  1. Adicione HTTP Request depois do webhook. Configure método POST, URL http://litellm:4000/v1/chat/completions, tipo do corpo JSON e Content-Type: application/json.
  2. No corpo JSON, use o modo Expression para inserir a expressão abaixo. O texto da pergunta vem do corpo recebido pelo webhook:
{{ ({
  model: "llama3.2:3b",
  messages: [
    { role: "system", content: "Responda em português de forma clara e objetiva." },
    { role: "user", content: $json.body.pergunta }
  ]
}) }}
  1. Configure autenticação pelo seletor de credenciais do HTTP Request: crie uma credencial genérica Header Auth com nome Authorization e valor Bearer <LITELLM_MASTER_KEY>. Para consultar sua chave, abra o .env na pasta do projeto (por exemplo, execute notepad .env no PowerShell nessa pasta) e copie o valor depois do sinal =. Salve a chave como credencial do n8n; não a escreva no prompt, no corpo JSON nem em screenshots compartilhados.
  2. Confirme que LiteLLM e Ollama estão ativos e que o modelo llama3.2:3b está disponível no Ollama. Um modelo pode demorar mais na primeira execução, especialmente em computadores sem GPU compatível.

Etapa C · Devolver uma resposta JSON

  1. Adicione Respond to Webhook depois do HTTP Request.
  2. Escolha Respond With = JSON. No corpo da resposta, use uma expressão para selecionar os campos desejados:
{{ ({
  resposta: $json.choices[0].message.content,
  modelo: $json.model
}) }}

Execute o workflow enquanto o webhook de teste estiver escutando. No PowerShell, envie esta requisição na máquina onde o laboratório está instalado:

$payload = @{ pergunta = "Explique em uma frase o que é uma API." } | ConvertTo-Json
Invoke-RestMethod `
  -Method Post `
  -Uri "http://localhost:5678/webhook-test/perguntar" `
  -ContentType "application/json" `
  -Body $payload

Após verificar o resultado, publique o workflow. A URL de produção usa /webhook/perguntar no lugar de /webhook-test/perguntar. A URL de teste só funciona enquanto o editor está aguardando um evento; a URL de produção funciona quando o workflow está publicado.

Observação sobre a interface

Os nomes e a posição de alguns controles variam entre versões do n8n. A lógica permanece: ativar a espera do webhook de teste, executar uma chamada HTTP com JSON, mapear o resultado e depois publicar para registrar o endpoint de produção.

06 · SERVIÇOS DO LABORATÓRIO

Endereços para integrações internas

Estes nomes de host só resolvem diretamente para aplicações conectadas à rede Docker do laboratório. Use-os nos nodes executados pelo n8n:

ServiçoEndereço internoUso comum
LiteLLMhttp://litellm:4000API de chat em /v1/chat/completions; embeddings em /v1/embeddings.
Python MCPhttp://python-mcp:8000Saúde em /health, tarefas REST em /run-task, MCP Streamable HTTP em /mcp.
Ollamahttp://ollama:11434API direta de modelos; para chamadas de chat neste laboratório, prefira o gateway LiteLLM.
Apache Tikahttp://tika:9998Extração de texto e metadados de documentos. Serviço opcional do perfil de documentos.
Browserlesshttp://browserless:3000Navegação headless e scraping; requer serviço ativo e token.
Qdranthttp://qdrant:6333Banco vetorial; requer uma coleção e um fluxo de ingestão/consulta de embeddings configurado.
Dentro do container, localhost significa o próprio container do n8n

Para acessar outro container, use o nome do serviço, como http://litellm:4000. Para chamar o webhook do n8n a partir do Windows, use http://localhost:5678/webhook/.... Um serviço opcional desligado não responderá, mesmo que o endereço esteja correto.

O Python MCP oferece uma API REST simples e também um endpoint MCP em http://python-mcp:8000/mcp. Para integrações MCP avançadas, confira se a versão instalada oferece os nodes de cliente MCP e siga as instruções oficiais para o transporte HTTP; o endpoint REST /run-task é a alternativa direta deste laboratório.

07 · IA E AGENTES

Quando usar um modelo ou um agente

Uma chamada de chat costuma bastar quando o workflow precisa resumir, classificar, extrair campos ou redigir texto. Um agente é adequado quando o modelo precisa escolher entre ferramentas disponíveis para cumprir uma tarefa. Quanto mais ferramentas e permissões forem dadas ao agente, maior a necessidade de limitar escopo e validar resultados.

  • Comece com uma tarefa delimitada e uma saída esperada. Peça JSON com campos definidos quando outra etapa for consumi-la.
  • Trate o texto recebido do usuário como dado; não permita que ele altere segredos, instruções de sistema ou controles do workflow.
  • Valide a resposta antes de usá-la para enviar mensagens, alterar dados ou chamar sistemas externos.
  • Registre e examine as execuções durante o desenvolvimento. Evite armazenar dados pessoais ou sensíveis sem necessidade.

O fluxo do exercício anterior usa a API de chat do LiteLLM por HTTP Request e oferece um ponto de partida simples para prompts. Para nodes de IA e agentes do n8n, a interface pode variar com a versão e os modelos disponíveis; conecte o node de modelo ao endpoint LiteLLM suportado pelo node e selecione o modelo publicado no gateway.

Desempenho e estabilidade

  • Comece com poucos itens e volumes pequenos; aumente o lote gradualmente. Respostas grandes e arquivos binários podem consumir bastante memória e armazenamento.
  • Evite paralelizar muitas chamadas ao modelo em computadores com pouca RAM ou VRAM. Ollama compartilha os recursos da máquina com os outros serviços.
  • Use paginação ou lotes para APIs que devolvem muitos registros. Evite repetir consultas ou transferir campos que o restante do fluxo não usa.
  • Configure tentativas e tratamento de erro considerando se a ação é segura para repetir; uma requisição POST pode criar itens duplicados.
  • Se o workflow tratar arquivos, limite tamanho e frequência e acompanhe o espaço usado pelo volume persistente.

08 · CICLO DE DESENVOLVIMENTO

Testar, salvar e publicar

  • Teste por node: execute uma etapa e confira Input e Output antes de avançar. Use exemplos pequenos.
  • Salvar: o n8n salva alterações no servidor enquanto você edita. Confirme que não há indicador de salvamento pendente antes de fechar.
  • Publicar: publique quando o workflow tiver um gatilho de produção, como webhook ou agendamento. A versão publicada é a que atende execuções de produção.
  • Despublicar: se não quiser mais receber eventos, despublique o workflow ou remova/desative o gatilho conforme o caso.
  • Executions: abra a aba de execuções para filtrar sucessos e falhas, examinar a entrada/saída e tentar novamente uma execução com falha.

Fluxos manuais são bons para aprendizagem. Antes de publicar, confirme o webhook de produção, as credenciais, os serviços dependentes, o formato da resposta e se a rotina pode ser repetida com segurança.

09 · SEGURANÇA E DADOS

Credenciais, webhooks e persistência

  • Guarde tokens e senhas em Credentials. Não os inclua em prompts, URLs, expressões, dados de teste ou screenshots.
  • O endpoint n8n deste projeto está publicado apenas em 127.0.0.1:5678 no host. Webhooks não são automaticamente acessíveis pela internet ou por outros computadores.
  • Configure autenticação no Webhook quando ele for consumido por outro sistema. O n8n oferece opções como Basic, Header e JWT; use allowlist de IP quando fizer sentido.
  • Evite expor a porta do n8n na rede sem planejamento de autenticação, HTTPS, firewall e atualizações. Um webhook publicado pode executar a lógica configurada sempre que for chamado.
  • As execuções podem conter prompts, respostas e dados recebidos. Limite o que grava e quem pode abrir a interface.
  • Não apague nem substitua N8N_ENCRYPTION_KEY no .env sem planejar a migração de credenciais existentes. Guarde backup seguro do .env.
  • Em Configurações, o reset de n8n apaga n8n_db e n8n_storage, incluindo workflows, credenciais e arquivos persistentes do serviço. Exporte o que quiser preservar antes.

10 · DIAGNÓSTICO

Problemas comuns e como resolver

A página do n8n não abre

Inicie n8n pelo dashboard. Confira se o PostgreSQL está saudável e se a porta 5678 não está ocupada. Consulte os logs do serviço n8n no painel/Docker.

Connection refused no HTTP Request

Dentro do container, troque localhost pelo hostname do serviço de destino, como litellm ou python-mcp. Confira se o serviço está iniciado e se pertence ao mesmo perfil/rede.

O LiteLLM retorna 401 ou 403

Verifique a credencial Header Auth do HTTP Request: cabeçalho Authorization e valor no formato Bearer .... Confirme que usou a chave de LiteLLM do .env, sem aspas ou espaços extras. Não compartilhe o valor da chave.

O modelo não existe ou demora para responder

Confira se o LiteLLM está ativo e se o Ollama possui o modelo solicitado. Veja os logs do LiteLLM/Ollama e confirme que o identificador usado no corpo corresponde a um modelo definido na configuração atual do gateway. Primeira carga pode demorar.

O webhook de teste retorna 404

No editor, selecione Listen for Test Event e envie a requisição para /webhook-test/... enquanto a espera estiver ativa. Para /webhook/..., publique o workflow e confirme o path configurado.

A resposta do webhook não tem o campo esperado

Abra a execução e confira o JSON de saída do node anterior. Corrija a expressão de acordo com a estrutura real; por exemplo, alguns endpoints retornam conteúdo em choices[0].message.content.

Credencial não pode ser descriptografada depois de reinstalar

Confirme que o arquivo .env mantém a mesma N8N_ENCRYPTION_KEY que foi usada pela instalação anterior. O banco e a chave precisam corresponder.
